# ADR-0008: Dependency policy — minimal, licence-checked, pinned per Python version

**Status:** Proposed
**Date:** 2026-10-04
**Deciders:** Fable 5.1, user (embodic licence) — consulted: Agent 3, Agent 4

## Context

- BRIEF §3 rule 7: record licences of every proposed dependency; GPL references (magnetless_motor GPL-3.0, kimotor
  GPL-2.0) are reference-only (DL D-003).
- IPC plugin dependencies are pip-installed into a per-plugin venv on first load (A5-KI §3, `verified`); offline install
  `unresolved` (G13) → the plugin's dependency footprint should stay small (A5-KI §5 item 4, `inferred`).
- Python version facts (PyPI metadata, 2026-10-04, `verified`): NumPy 2.5.x requires Python ≥ 3.12; 2.4.6 is the newest
  NumPy with `cp311-win_amd64` wheels; Pint 0.26 requires ≥ 3.12; PySide6 6.11.2 supports ≥ 3.10, < 3.15. The user's
  minimum is 3.11 (BRIEF §1); KiCad 9.x's bundled Python version is `unresolved` (A5-KI T1).
- Xcoil v3 writes SVG, DXF, `.kicad_pcb`, ZIP and PDF without libraries and validates them with independent parsers in
  tests (`engine.js` l.2796–2966, `report.js` header "a dependency-free PDF writer", `validate_exports.py` — `verified`).

## Decision

1. **Core runtime** (`embodic` without extras): Python standard library + **NumPy** only.
2. **Extras**: `desktop` → `PySide6-Essentials` (not the `PySide6` meta-package, which adds the 168 MB Addons wheel);
   `kicad` → `kicad-python`. Nothing else at runtime.
3. **In-house writers** for SVG, DXF R12, `.kicad_pcb` (s-expression), JSON/CSV and PDF (port of our own Xcoil code —
   permitted: it is our prior work, BRIEF §2), validated by independent parsers in tests.
4. **Licence allow-list for distributed artefacts**: MIT, BSD-2/3-Clause, Apache-2.0, PSF, ISC, Zlib, 0BSD, CC0-1.0, MPL-2.0
   (file-level copyleft, unmodified use) and LGPL-3.0 (Qt, dynamic linking only, with notice and source offer). GPL/AGPL
   only for test/build tools that are not distributed with embodic (e.g. kiutils GPL-3.0 as a test parser; PyInstaller
   GPL-2.0 with bundling exception). If the user chooses GPL-3.0 for embodic, the list widens accordingly.
5. **Version policy**: compatible ranges in `pyproject.toml` with environment markers. Provisional NumPy range, adopted
   from Agent 3 (`docs/phase1/software/dependency_and_tooling_draft.md` §1): `numpy>=1.26,<2.5` (1.26.4 supports
   Python ≥ 3.9, in case KiCad's bundled Python is older; 2.4.x is the last line for 3.11); after T1/T2 split by marker,
   e.g. `numpy>=X,<2.5; python_version<"3.12"` and `numpy>=X,<3; python_version>="3.12"`. Exact pins with hashes in
   per-Python lock files (`requirements/py311.txt` …) generated by pip-tools (BSD) or uv (MIT/Apache-2.0).
6. **Gate for a new dependency**: amendment row in this ADR with purpose, SPDX licence, last release date, maintainers,
   native code yes/no, Windows wheels for 3.11–3.13, installed size, alternatives; Fable approves.
7. **CI**: `pip-licenses` (MIT) allow-list check, `pip-audit` (Apache-2.0) vulnerability scan, THIRD_PARTY_LICENSES
   generation.

## Options Considered

### Option A: Minimal core (stdlib + NumPy), in-house writers, allow-list (chosen)
| Dimension | Assessment |
|---|---|
| Complexity | Medium — own writers to maintain |
| Cost | Low install footprint; proven Xcoil code to port |
| Scalability | High |
| Team familiarity | High |

**Pros:** small plugin venv; few licence obligations; fewer upgrade breakages. **Cons:** writers are our responsibility
(mitigated by independent parser tests).

### Option B: Library-rich core (ezdxf, reportlab, Shapely, pydantic at runtime)
| Dimension | Assessment |
|---|---|
| Complexity | Low per feature |
| Cost | Larger footprint; native deps (Shapely/GEOS; reportlab requires pillow per PyPI) |
| Scalability | Medium |
| Team familiarity | Medium |

**Pros:** less own code. **Cons:** heavier first-load install in KiCad's venv; more licences and version conflicts (e.g.
kicad-python pins protobuf < 6, PyPI `verified`).

### Option C: No NumPy (pure Python core)
**Pros:** zero native deps. **Cons:** DRC/EMF performance risk against REQ-N-01 (`inferred`). Rejected for now; revisit if
T2 shows NumPy cannot be installed in KiCad's venv.

## Trade-off Analysis

The plugin context and the licence rule favour a minimal runtime set; NumPy is the one dependency that buys a large
performance margin for array kernels.

## Consequences

- Easier: reproducible installs, clean licence report, robust plugin venv.
- Harder: per-Python lock files and markers; maintaining writers.
- Revisit: after T1/T2 (bundled Python version, NumPy install in the plugin venv) and after the user's licence decision.
