# UX acceptance criteria v1 (UX-AC, Phase 2 desktop)

Date 2026-10-04, revised 2026-10-08 (U-S4c: UX-AC-16 stack mode, UX-AC-25, UX-AC-26), revised 2026-10-09 (U-S4d:
UX-AC-03, 05, 11, 21, 27; rulings in `m4_review.md`), revised 2026-10-09 (U-S4e: UX-AC-03, 08, 21, 27; rulings in
`m4_review_2.md`). Replaces the Phase 1 list in `docs/phase1/design/design_handoff_for_agent3.md` section 4. Phone and
KiCad criteria are dropped (D-009, D-010). Each criterion names a test that drives the PySide6 app (offscreen
`QT_QPA_PLATFORM=offscreen` is acceptable unless the row says Windows). Agent 6 maps them to requirement ids; Agent 4
writes the independent tests.

| Id | Criterion | How to test |
|---|---|---|
| UX-AC-01 | Every numeric result shows value, unit (or "–" with accessible text "dimensionless"), exactly one trust badge (D-007) and one "n assumptions" tag. | Walk every `res-card-*`: children `-value`, `-unit`, `-badge` (one), `-asm` exist and are visible. |
| UX-AC-02 | Every computed result has an EQ-ID link or an `input`, `derived` or `count` tag, and a "How was this computed" section with equation, inputs with units and provenance, assumptions, limitations, validation and sources. | Expand each `res-<key>-how`; assert the six parts are non-empty. |
| UX-AC-03 | No visible string contains "Xcoil", "KiCad", Thai characters, a repository path or a personal name. Example titles follow the pattern of `m4_review_2.md` ruling g and contain neither "Example" nor "default". | Collect `text()`, `toolTip()`, `windowTitle()`, `accessibleName()` of all widgets, the examples gallery items included, and the exported files (the JSON project of each loaded example included); regex scan. Assert the five gallery titles equal the ruling g list. |
| UX-AC-04 | Chrome uses only neutral tokens; colour appears only on phase marks, legends, charts and status text. | Parse the loaded style sheet: every hex outside status and phase hooks is a neutral token in `tokens.json`; grab the window in both themes and check non-grey pixels lie inside the canvas, charts, badges or status labels. |
| UX-AC-05 | Phases and polarity stay distinguishable without colour in every mode, on the canvas and in the SVG and PDF: phase labels per `design_spec.md` 3.3, coil-eye fill (tint, 45 degree, 135 degree hatch) inside the eye only, solid copper, chart line style (solid, dashed, dotted), legend. | Render D08 in colour and greyscale on the canvas and to SVG and PDF; assert 12 labels with phase and sign, one eye fill per coil clipped to its disc, no dashed copper, a legend; a reviewer names phase and polarity of all 12 coils from the greyscale PDF (REQ-N-14). |
| UX-AC-06 | Theme switch: View > Theme and Ctrl+Shift+T switch light and dark without restart, keep the current tab, selection and zoom, rebuild every icon in the new icon colour, and persist the choice. | Switch theme; compare `QApplication.styleSheet()` with `dark.qss`; sample an icon pixel equals `icon_color.normal`; restart reads the saved theme. |
| UX-AC-07 | Greyscale mode: View > Greyscale and G on the canvas switch phases to the greyscale ladder with hatching; the PDF report offers the same mode. | Toggle; sample copper pixel colours equal `phase-*-grey` of the theme. |
| UX-AC-08 | Text contrast is 4.5:1 or more, control boundaries, focus ring and phase strokes 3:1 or more, in both themes. | Recompute `tokens.json` > `contrast_pairs`; no pair below its minimum. Grab a selected `examples-list` item in both themes; its title and note pixels reach 4.5:1 on the selection (the U-M4c-3 shot measured 3.18:1). |
| UX-AC-09 | Every toolstrip button has an icon, a visible label (or an accessible name when collapsed), and a tooltip "Label (Shortcut). Sentence."; a disabled button's tooltip names why. | Iterate `#toolstrip` QToolButtons; assert `icon()` not null, `toolTip()` matches the pattern, shortcut text equals `design_spec.md` section 6. |
| UX-AC-10 | Keyboard map in `design_spec.md` section 10 works; every command is reachable without a mouse; F6 cycles the regions; single-letter keys act only while the canvas has focus. | `QTest.keyClick` per row; assert the action fired; assert "L" in a text field types "L". |
| UX-AC-11 | Visible focus indicator on every focusable widget (2 px `focus-ring`), drawn by the style sheet, not by widget code. | Tab through the window; grab each focused widget; ring pixels equal `focus-ring`. `tools/design/qss_smoke.py` passes. |
| UX-AC-12 | No silent value rewrite: when the engine changes a user value, an inline notice "Changed from X to Y: reason" with Undo appears beside the field and is announced; Undo restores X. Re-typing a default value changes no status (D-007). | Scripted clamp case; assert notice text, then Undo; assert badge and assumption count unchanged after re-typing a default. |
| UX-AC-13 | New-design flow: the app opens on the New design dialog; **Create design** enables once the name is valid and a topology is chosen, and opens the draft in the inspector. Required fields start empty and optional fields show their default with a `default` chip. `new-required-count` shows the number of missing pointers, **Go to first missing field** focuses the first one, and nothing computes until `parse_draft` returns `DesignParameters` (`screens.md` v2, R11). | Start app; assert the button is disabled until name and topology are set. Create a blank design per topology; assert empty required fields, `default` chips, no compute call (spy on the worker). Fill the pointers of `screens.md` section 16 one by one; assert the count falls and compute starts after the last. |
| UX-AC-14 | Examples load with `example` chips; editing a field turns its chip to `user`; marking measured needs a named source. | Load an example; check chips; edit; check chip; "Mark as measured" without a source is refused. |
| UX-AC-15 | Required-field and range validation: invalid input sets `invalid=true`, shows the message under the field and in Checks; the last valid geometry and results stay dimmed with "Last valid" stamps. | Enter out-of-range values per field; assert the property, the message text equal to `embodic.errors.MESSAGES` of the issue code (R14), and the stale stamps. |
| UX-AC-16 | Fields that do not apply to the active topology or option are hidden; a temporarily blocked field is disabled with its reason. | Config matrix: three topologies x end style x rotation mode x outline shape x magnet shape x stack mode; assert visibility per `screens.md`. With one board per phase `param-layer-order` is disabled with its hint; with a single board `param-board-gap` is. |
| UX-AC-17 | Every input shows its unit and the unit is in the accessible description. | For each `param-*` with a unit, assert `<id>-unit` visible and `accessibleDescription()` contains it. |
| UX-AC-18 | Export with DRC failures requires a confirmation that lists the failures; focus starts on Cancel. Exported files carry embodic version, engine version and parameter hash. | Scripted export; assert dialog, focus, file headers. |
| UX-AC-19 | Charts: one unit per y axis; legend and direct labels for two or more series; data table available; crosshair reachable by keyboard. | Chart audit per `chart-*`. |
| UX-AC-20 | Counts show as integers; compare deltas use sign plus glyph, never red or green. | Formatting test on `compare-table`. |
| UX-AC-21 | Window minimum 960 x 540 px; two panes from 960 px, three panes from 1280 px; no clipped toolstrip button at 960 px (small buttons may collapse to icons with accessible names); no result card, badge, unit or tab label clipped at any size. Vertically (`design_spec.md` 5): the canvas page holds 60 % of the centre height by default and never less than 240 px; under 620 px client height the canvas is the "Drawing" tab. `layer-list`, `pair-list`, `screw-table`, `drc-table` and the result card grid never scroll sideways from 960 px wide. | With the bundled fonts registered: resize to 960 x 540, 1280 x 720, 1280 x 800, 1920 x 1080 on D08 and wave; assert the pane count and widths (300; 340 and 360), every label's height at least its size hint, every toolstrip button visible or in the overflow, canvas height at least 240 px or the Drawing tab present at 960 x 540, and `horizontalScrollBar().maximum() == 0` for the five views. Drag the split, restart, assert the share is restored. |
| UX-AC-22 | Recompute: results update within 300 ms of the last edit for the default example, or show "Updating" with previous values dimmed. | Timing test (`unresolved` target until the Python engine is measured). |
| UX-AC-23 | No animation runs by default; current-flow arrows are static. | Inspect timers and `QPropertyAnimation` instances after start. |
| UX-AC-24 | High-DPI and Windows: the UI renders without clipped text at 100 %, 150 % and 200 % scaling and in Windows high contrast. | Manual check on Windows (`not tested` until Phase 3). |
| UX-AC-25 | Spiral layer pairs follow the copper count (D-024, `screens.md` section 4): pairs appear when the count is set, new pairs show a `default` rotation chip, user edits survive a count change, an odd count shows the `RANGE_SPIRAL_COPPER_COUNT_ODD` WARNING text without `invalid=true`, a removed pair returns on a later count change, and `layer-pairs-notice` says so. | Blank spiral: set the three stack-up inputs to 4 copper layers; assert 2 pair rows with `default` chips. Edit pair 2's rotation; change to 6 layers; assert pair 2 keeps the value and `user` chip and pair 3 shows `default`. Delete pair 2 (the middle one); assert the notice text; change to 8 layers; assert 4 pairs with distinct indices, pair 2 back at the default on L3 and L4, pair 3 still on L5 and L6. Remove one copper row; assert the warning text equals `MESSAGES["RANGE_SPIRAL_COPPER_COUNT_ODD"]` and compute runs. Undo after each step restores the previous rows. |
| UX-AC-26 | Board picker (`assumption`, `screens.md` section 4.1): `board-picker` shows only for one board per phase, starts at "All boards", changes the canvas and nothing else, and DRC lists every board whatever the picker shows. | Serpentine, one board per phase, three phases: assert the picker is visible with four items and hidden after switching to a single board or to spiral. Select "Board B"; assert the scene holds only the copper of `BoardStack.boards[1]` and that results and the export file list are unchanged. Plant a violation on `boards[2]`; select "Board A"; assert the `drc-table` row is present with Board C and that **Locate** sets the picker to "Board C". |
| UX-AC-27 | Label density (`design_spec.md` 3.3): no two phase labels overlap at any zoom, every phase letter shows at fit zoom, wave labels read phase and sign, serpentine labels read the phase letter with 4 per phase. Both signs of each phase show at fit zoom (wave, spiral); every phase with copper in the view has a label inside the view; no label or leader crosses the view edge; fit zoom survives a resize. | Load wave and serpentine; at fit zoom and at 3x assert no two label boxes intersect, each phase has a label, the label texts match the pattern per topology. Wave at fit: labels "A+" and "A−" (and B, C) both present. Zoom to a region holding only phase B copper's sides: a "B" label lies in the view. Resize 1280 x 800 to 960 x 700 after load: the ring still fills the canvas within 10 %. |
