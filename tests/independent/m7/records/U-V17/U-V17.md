## Model changes

- Rule 5. `_tees` exempts an end group from the landing group of each primitive its end point lies on, in another path
  of the same net on the end's layer. `_landing_group` is the contract text: a main with the fillets and tapers that
  belong to it; a fillet or taper with the mains it belongs to and the run of consecutive fillets and tapers that holds
  it. The model reads "the other fillets and tapers between those main primitives" as that run; at a path end the run
  lies between the path end and the one main (`assumption`, no packaged path starts or ends with two corner pieces).
- Rule 2 tap. `_interconnect_taps` and `_on_centreline` are gone. `_via_taps` pairs a via with each primitive whose
  centreline passes within pad/2 of its centre: same net (rule 2b, `VIA_TAP`) or, for an interconnect path, any net
  (`INTERCONNECT_TAP`). A same-net via on an interconnect path is now labelled `VIA_TAP`, the rule that needs no waiver.
- The old `_tees` had no layer test. It exempted cross-layer pairs, which the sweep never checks, so no verdict changed.

## Q3: the tap over pads. Ruling: the model was wider than the contract; the tap names vias only

`verified` by running `m7/u_v17_model.py` (`U-V17_model_run.txt`). An N interconnect line with a round 0.6 mm pad
centred on it mid-path, no path end in the pad, pad of net N or PHASE_A:

| Reading | Pad pair |
|---|---|
| model at bbcaeff (`_interconnect_taps` over `_LANDS`) | exempt (`INTERCONNECT_TAP`) |
| model U-V17 | `pad_trace` at -0.400 mm |
| `run_drc` on bbcaeff | `pad_trace` at -0.400 mm |

Section 7 names vias in the tap and in rule 2b, and exempts a pad from an interconnect only where the path end lies in
the pad (rule 2). The old reach also mattered on a shipped board: on wave_16p_example the old model exempted
`pad:0` / `path:93/prim:0`, `pad:1` / `path:94/prim:0` and `pad:2` / `path:95/prim:0` because the lead's second
primitive ends in the pad. Each pair is 0.400 mm apart (rule 0.2 mm), so it is now checked and passes.
